# 故事稿模板

> 复制本文件填充内容。方括号内为待填项，`*` 为必须来自用户真实经历的事实。事实核对表里的编号要在稿子里能对应到。

```
## 一、五要素拆解（缺失项必须追问，不代编）
- 背景 *： [谁、何时、在什么情境下]
- 冲突 *： [卡在哪、撞上了什么]
- 转折 *： [事情怎么起了变化]  ← 缺失必须追问
- 结果 *： [最后怎样]            ← 缺失必须追问
- 我的变化： [这件事之后我哪不一样了 / 学到了什么]

## 二、3 个候选开头（前 3 秒留人，写法见 references/opening-hooks.md）
- 候选 A（[写法类型]）：[具体冲突或反常识陈述]
- 候选 B（[写法类型]）：[具体冲突或反常识陈述]
- 候选 C（[写法类型]）：[具体冲突或反常识陈述]

## 三、正文稿（含讲读标注；/ 停顿，**加粗** 重音，‖ 换气）
[钩子，取自候选开头之一]
[背景两句]
[冲突递进]
[转折]
[结果]
[观点收尾，取自用户选定观点或候选]

## 四、字数与时长核对
- 目标时长：[60 秒 / 3 分钟]，目标字数约 [240 / 700] 字
- 实际字数：[N] 字
- 结论：[在范围内 / 超出 X%，见第六节可删段落]

## 五、事实核对表（编号逐条请用户确认是否属实）
| 编号 | 类型 | 稿中表述 | 原文依据 | 请确认 |
|---|---|---|---|---|
| 核对 1 | 时间 | [如「等了三天」] | [用户原话] | 属实？ |
| 核对 2 | 数字 | [如「四个半小时」] | [用户原话] | 属实？ |
| 核对 3 | 引述 | [如「重做」] | [用户原话] | 属实？ |
| 核对 4 | 动作 | [具体动作] | [用户原话] | 属实？ |

## 六、可删段落建议（仅超字数时填写，不静默删减）
- 可删第 [X] 段：[内容摘要]，约省 [N] 字。删不删由你定。
```

## 填写约束

1. 五要素里「转折」「结果」缺失必须追问，不能空着编。
2. 开头必须给 3 个，且至少两个不同写法类型。
3. 事实核对表要覆盖时间 / 数字 / 引述 / 动作四类，不能只列数字。
4. 超字数只标可删段落，不替用户删。
